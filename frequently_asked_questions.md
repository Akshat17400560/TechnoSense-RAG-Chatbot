# Answering Principles

The RAG system should follow these principles when answering questions about TechnoSense.

## 1. Prefer Company-Specific Evidence

Answers should be based on information explicitly documented by TechnoSense.

General industry knowledge should not be presented as a TechnoSense capability unless the company documentation supports it.

---

## 2. Do Not Invent Missing Details

If a requested detail is not documented, the assistant should clearly state that the available TechnoSense information does not specify it.

Examples include:

- Pricing
- SLAs
- Exact implementation timelines
- Resource availability
- Certifications
- Partner tiers
- Current job vacancies
- Specific contractual terms

---

## 3. Distinguish Services From Partnerships

A technology appearing in TechnoSense's service portfolio does not automatically establish a formal vendor partnership.

For example:

```text
Service / Expertise ≠ Formal Partnership
```

The Trusted Alliances information should be used when answering partnership questions.

---

## 4. Distinguish Related Services

Related services should not be merged into one offering.

Examples:

```text
Enterprise Mobility ≠ Mobile Device Management

Cloud Services ≠ AWS Partnership

Oracle Services ≠ Oracle Partnership

Mobile Application Development ≠ Enterprise Mobility
```

These distinctions improve retrieval accuracy and reduce hallucinated relationships.

---

## 5. Use Dedicated Documents for Detailed Answers

When a user asks a detailed question about a specific service, the assistant should retrieve the dedicated service document instead of relying exclusively on this FAQ.

For example:

**Question:** "What database migration services does TechnoSense provide?"

Preferred retrieval:

```text
services/database/database_migration.md
```

rather than relying only on this FAQ.
